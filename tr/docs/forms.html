Temel kavramlar

Formlar ve İki Yönlü Bağlama

Tek yönlü value+oninput, bindings.model ve x-model ile iki yönlü bağ, select, onsubmit ve fonksiyon action ile form gönderimi, doğrulama deseni; JSX ile ve JSX'siz.

MotifJS form girdilerini iki yolla yönetir:

  1. Reaktif okuma + olay yazma (tek yönlü, açık): value={() => note.title} + oninput.
  2. İki yönlü bağ (bindings.model, JSX'te x-model): girdi ile model otomatik senkronize olur. Belirli bir DOM özelliğine tek yönlü bağ için bindings.add kullanılır.

Örnekler not uygulamasının kesitleridir. Note ve NotesService Bileşenler sayfasındaki src/services/notes.ts dosyasındakilerdir, SettingsService ve THEMES Başlarken sayfasındaki src/services/settings.ts dosyasından gelir; note düzenlenen nottur.

Tek yönlü (açık) yaklaşım

Değeri reaktif okursunuz, değişikliği olayla modele yazarsınız. Değişimde ek iş (dönüştürme, doğrulama, yan etki) olduğunda bu yol seçilir:

<form>
  <input type="text" value={() => note.title} oninput={(e) => (note.title = (e.target as HTMLInputElement).value)} />
  <input type="checkbox" checked={() => note.pinned} onchange={(e) => (note.pinned = (e.target as HTMLInputElement).checked)} />
</form>
motifComponent("form", (form: ComponentBase) => {
  const title = motifComponent("input", (input: ComponentBase) => {
    input.attr.add({ type: "text" });
    input.bindings.add("value", () => note.title);
    input.motif.on("input", (_sender: ComponentBase, e: Event) => (note.title = (e.target as HTMLInputElement).value));
  });
  const pinned = motifComponent("input", (input: ComponentBase) => {
    input.attr.add({ type: "checkbox" });
    input.bindings.add("checked", () => note.pinned);
    input.motif.on("change", (_sender: ComponentBase, e: Event) => (note.pinned = (e.target as HTMLInputElement).checked));
  });
  form.controls.add(title, pinned);
});

value ve checked özellik bağıdır: JSX'te etikete yazılan value={() => …} bindings.add("value", getter) çağrısına derlenir, öznitelik yazılmaz.

İki yönlü bağ — bindings.model

bindings.model, elemanın türüne göre doğru DOM özelliğini otomatik seçip modele iki yönlü bağlar:

Eleman Bağlanan özellik
<input type="checkbox">, <input type="radio"> checked (boolean)
<input> (diğer) value
<select> value
<textarea> value
<img>, <audio>, <video> src (tek yönlü: yalnız model → eleman)

Input'larda checked/value seçimi bağ kurulurken değil, her okuma/yazmada elemanın o anki type'ına göre yapılır: onConfig bağı kurduğunda type attribute'u henüz uygulanmamış olabilir.

Modele yazılan değerin türü de elemana göre belirlenir:

Girdi Modele yazılan
checkbox, radio boolean
number, range number (girdi boşaltılırsa null)
diğer hepsi (text, date, select, textarea…) string

Tarih türleri bilerek dizge kalır: doğal modelleri '2026-10-16' biçimidir.

JSX'te bağ onConfig içinde kurulur: bileşen yapılandırılırken bağ eklenir. JSX'siz yazımda kurulum fonksiyonunun kendisi bu yerdir.

İmzalar:

Çağrı Bağlanan değer
model(dataSource, dataMember) dataSource üzerindeki dataMember alanı
model(dataSource, dataMember, formatString) Aynı alan, formatString ile biçimlenmiş
model(dataSource, dataMember, formatString, formatInfo) Aynı alan; yerel ayar ve para birimi formatInfo'dan ({ locale, currency })
model(getter, setter) Okuma getter(), yazma setter(değer)
model(binding) Hazır bir bağ nesnesi

Her biçim eklenen bağı (IBaseBinding) döndürür.

dataMember noktalı yol da olabilir ("meta.category"). Tek argümanlı çağrıda nesne bir IBaseBinding olarak yorumlanır; tek argümanlı bir fonksiyon ise yalnız okur, tek yönlü bağlar. model(dataSource, dataMember) çağrıldığı andaki dataSource nesnesini tutar; o nesne bütünüyle değiştirilebiliyorsa x-model ya da getter/setter biçimini kullanın.

Kendi bileşeninde x-model

Elemanı form elemanı olmayan bir bileşen de x-model ile kullanılabilir. Bağlı değer bileşenin value özelliğine yazılır; bileşen kendi value özelliğini tanımlıyorsa elemanı <button> gibi kendi value alanı olan bir eleman olsa da değer bileşene gider. Bileşen yeni değeri modele bindings.writeModel(değer) ile geri yazar (sınıfta ve Options'ta this.bindings, fonksiyon bileşeninde kök bileşenin bindings'i). PinSwitch bir notun sabitlenmesini açıp kapatan bir düğmedir: sınıfta ve Options'ta value bir erişicidir (get/set), fonksiyonda erişici kökün initializeComponent kancasında Object.defineProperty ile kurulur:

import { Component, reactive } from "@motifx/core";

export class PinSwitch extends Component<HTMLButtonElement> {
  state = reactive({ on: false });

  set value(v: boolean) { this.state.on = !!v; }
  get value() { return this.state.on; }

  override onConfigured() {
    this.attr.add({ type: "button" });
    this.class.add("switch");
    this.motif.on("click", () => this.bindings.writeModel(!this.state.on));
  }

  override view() {
    return <>{() => (this.state.on ? "Sabit" : "Serbest")}</>;
  }
}

import { reactive } from "@motifx/core";

export function PinSwitch() {
  const state = reactive({ on: false });
  return (
    <button
      type="button"
      class="switch"
      initializeComponent={(root) => Object.defineProperty(root, "value", { get: () => state.on, set: (v: boolean) => (state.on = !!v), configurable: true })}
      onclick={(root, _e) => root.bindings.writeModel(!state.on)}
    >
      {() => (state.on ? "Sabit" : "Serbest")}
    </button>
  );
}

Form gönderimi

NoteForm yeni notun alanlarını x-model ile bir taslağa bağlar ve gönderimde servise yazar. onsubmit:prevent sayfanın yeniden yüklenmesini engeller; JSX'siz yazımda aynı değiştirici motif.on("submit:prevent", …) ile verilir:

import { Component, reactive } from "@motifx/core";
import { NotesService } from "../services/notes";

export class NoteForm extends Component {
  notes = this.getService(NotesService)!;
  draft = reactive({ title: "", body: "", pinned: false, due: "" });

  save() {
    const note = this.notes.create();
    note.title = this.draft.title;
    note.body = this.draft.body;
    note.pinned = this.draft.pinned;
    this.draft.title = "";
    this.draft.body = "";
    this.draft.due = "";
  }

  override view() {
    return (
      <form class="note-form" onsubmit:prevent={() => this.save()}>
        <input type="text" placeholder="Başlık" x-model={() => this.draft.title} />
        <textarea placeholder="İçerik" x-model={() => this.draft.body} />
        <label><input type="checkbox" x-model={() => this.draft.pinned} /> Sabitle</label>
        <input type="date" x-model={() => this.draft.due} />
        <button type="submit" disabled={() => !this.draft.title.trim()}>Kaydet</button>
      </form>
    );
  }
}

onsubmit={(sender, e) => { e.preventDefault(); save(); }} aynı işi blok gövdeyle yapar. Eleman metotları JSX prop'u olarak yazıldığında öznitelik yazılmaz, metot çağrılır: <form requestSubmit={() => draft.send}>, <input focus={() => draft.editing} /> (false → blur()), <input setSelectionRange={[0, 5]} />. reportValidity, checkValidity, select, reset, submit de bu gruptadır; tam liste ve değer kuralları için Eleman metotları.

Fonksiyon bileşeninde search ve refresh bileşen fonksiyonunun içindeki yerel fonksiyonlar, state reactive ile kurulan yerel durumdur.

Değer her öznitelikte olduğu gibi getter içinde okunur. Sonuç fonksiyonsa öznitelik yazılmaz, fonksiyon gönderim işleyicisi olur; dizeyse URL olarak yazılır ve canlı kalır (action="/ara", action={state.url}). JSX'siz yazımda değer bu yüzden getter ile verilir: attr.add({ action: () => search }) işleyiciyi bağlar, attr.add({ action: search }) ise search'ü getter sayar ve sonucunu yazar. motif-explain bu özniteliği attr.action olarak gösterir.

Gönderimde önce formun kendi onsubmit işleyicileri çalışır; biri preventDefault() çağırdıysa (onsubmit:prevent dahil) fonksiyon çağrılmaz. Aksi durumda çerçeve preventDefault() çağırır, new FormData(form, gönderici) kurar ve fonksiyonu olay işleyicilerinin kuralıyla çağırır: tek parametre (data), iki parametre (sender, data); sender özniteliği taşıyan bileşendir, action için form, formaction için düğme. Gönderici düğmenin name/value çifti data'nın içindedir. Göndericinin formaction'ı fonksiyonsa formun action'ının önüne geçer; dizeyse gönderimi tarayıcı yapar. form.requestSubmit() fonksiyonu çalıştırır; form.submit() olay üretmediği için çalıştırmaz. Fonksiyon atarsa ya da döndürdüğü promise reddedilirse hata MJX123 ile raporlanır (bkz. Hata Yönetimi). Form gönderimden sonra sıfırlanmaz; boşalması gereken alanı fonksiyon kendisi boşaltır.

  }
};

Yöntem karşılaştırması

Yöntem Ne zaman
Tek yönlü (value + oninput) Değişimde ek mantık (dönüştürme, doğrulama, yan etki) çalıştıracaksanız.
bindings.model / x-model İki yönlü senkronizasyon yeterliyse; en az kod.
bindings.add("checked"/"value", ...) + olay Bağlanacak özelliği elle seçmek istiyorsanız (tek yönlü; geri yazma olayla).
onsubmit:prevent Alanlar modele bağlıysa; gönderim yalnız işlemi tetikler.
action={fn} Alanlar bağlı değilse ve değerleri FormData olarak tek seferde almak istiyorsanız; düğme başına formaction ile farklı işlemler.
